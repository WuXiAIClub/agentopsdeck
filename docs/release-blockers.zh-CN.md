# 发布阻断推进流程

## 证据与授权分开

AgentOpsDeck 1.0.0 仍是草稿。源码扫描、依赖审计、许可证文件检查或定向回归
通过，都不授权公开发布。GitHub 登录暂缓；未授权提交、推送、打标签或部署。
历史检查点见[源码审查](open-source-review-1.0.0.zh-CN.md)与
[验证记录](validation-1.0.0.md)。

| 阻断 | 所需证据 | 当前处理方式 |
| --- | --- | --- |
| 源码缺陷 | 最小修复、回归及当前字节的语义审查 | 分批修复 API、执行、脚本和界面，保留独立缺口 |
| 源码审查未完成 | 完整读文件及必要直接契约 | structural 清单不等于 semantic 通过 |
| 外部契约 | 指定实现及匹配版本的契约审查 | 历史 2.3.7 提交已找到，可只读调查；不能用当前 2.5.0 替代 |
| Hermes 网关契约 | 指定 replay/server/entry 源码身份及明确的信任审查 | 实现尚未提供；不得靠执行任意上游代码消除阻断 |
| 继承代码权属 | 实际权利人对源码、贡献及资源的授权 | Apache-2.0 选择及新 Git 作者不证明继承版权 |
| 发行物归属声明 | 实际分发文件清单、完整许可证／声明及适用源码义务 | 包元数据只是起点；未批准镜像或原生发行物 |
| 实际验收 | 有日期的命令／结果、排除项与真实运行／平台证据 | 允许本地隔离测试；不授权业务历史上游重放及生产维护 |
| 发布授权 | 对最终精确源码及分发范围的明确批准 | 仍待批准；GitHub 登录不等于发布授权 |

## 外部契约检查点 — 2026 年 11 月 23 日

已经找回指定历史 2.3.7 提交及 15 份可识别源码，并进行只读检查。这替代
11 月 22 日“基线不可用”的观察，但**没有**关闭兼容性问题 `S1-009`。
验证器仍从新仓库解析历史，而新仓库按要求不保留继承提交历史。未经适配的历史
配置不识别当前 `AOD_*` 隔离设置；历史构建导出、身份、协议及文件绑定头还需
审核规范化契约。禁止直接执行原始历史基线、导入其 Git 历史或用其他版本替代。
仍需可核验来源的适配器和隔离前后对照 fixture；另一项单独提供的 Hermes
网关 ABI 仍缺少实现。

源码问题也与这些外部契约分开：通用执行恢复的持久回执缺口
`EXE-APP-COMPLETE-003`、并发文件系统变更边界 `AOD-API-COMP-001`，不会被
本轮日志、输出预算或 API 请求体修复顺带关闭。结果未知的执行仍禁止重放。

## 修复与验收检查点 — 2026 年 11 月 23 日

本轮定点修复沿用现有架构：

- Connector 成功探针使用显式 DTO 与公开 URL 字段，不转发任意上游对象。
  消息、创建与模型上传先限制实际传输字节；旧归档／置顶上传补齐有界读取及最终
  原 token／中断核对，保留原有畸形 JSON 的默认行为。
- 模型覆盖配置的启动与写入共用完整对象校验：键／模型最长 128 字符、最多
  512 项、编码后 UTF-8 最多 64 KiB。不支持的更新与已有无效文件在持久化或 ACK
  前失败；合法边界值可重新加载。外层设置 API 允许 4096 字符，不表示此运行时
  能持久化所有该范围的值。
- 可选完成标记存储失败不再阻断已有会话。创建弹窗使用原生模态；窄屏调用方现在
  转交并等待创建 Promise，不再立即关闭处理中控件。减弱动态效果时保留可见的
  静态启动状态与进度。
- 兼容／权限探针保留原始传输归属与执行身份；超时不等于已停止，不重放未知结果。

父智能体实际运行的 API 投影／正文／偏好测试通过 **83/83**；另一个六文件偏好／
设置兼容选集通过 **114/114**。模型覆盖／输出／环境与设置 ACK 通过 **30/30**
（17 + 13）；选集存在重叠，不应相加作为独立覆盖。运行时首次组合测试因重复的
合成队列 ID 失败；重跑采用独立 ID，保留队列／执行不变与未知结果保护断言。
此前中断、堆内存耗尽或 fixture 失败均不计为成功。

最终当前源码的 Web 测试通过 **1356/1356**，脚本测试通过 **665/665**，两者均无
失败、取消或跳过。这些结果只覆盖各自测试运行器，不代表完整后端或远端 GitHub CI
通过。草稿门禁成功不是发布批准；完整审查与发布门禁仍须拒绝未闭环阻断。

整合后的精确字节台账覆盖 **3567 个文件**：**839 个语义审查**、**2719 个结构
审查**、**2 个待审**及 **7 个资源**。注册表包含 **139 条记录**，其中 **90 条**
有定点验证标签，但只有 **85 条**满足闭环证据契约，发布仍有 **54 条**未闭环。
记录包含相互重叠的观察和验收缺口，不是独立漏洞数量。结构覆盖不是语义批准，
仅有标签也不能关闭问题。这些是当日快照，以当前 JSON 台账和注册表为准。

真实无头浏览器 fixture 的创建／恢复在 **1440/390 px** 通过，启动／认证／存储
恢复在 **1440/390/320 px** 通过。创建核对原生模态焦点约束、背景 inert、
Escape／取消／关闭焦点恢复、认证关闭及处理中禁用控件。两个启动阶段通常各测得
**11** 个元素／伪元素动画条目，减弱动态效果时为 **0**，状态／进度可见，
fallback／认证／欢迎生命周期完成。HTTP／WebSocket 围栏与合成账号禁止访问上游
或重放业务历史。视口模拟不等于真实触控、读屏或原生平台验收；既有浏览器可执行
文件的分发来源未认证。这些 fixture 不批准全部 UI 源码或 CSS。

最新含开发依赖的注册表审计各严重级别均为 **0** 告警。部分已安装 LICENSE／NOTICE
文件哈希记录于[清单](review/third-party-license-inventory.json)，明确仅为清单。
两者均不构成完整依赖、发行物、权属或平台审查。当前 shared／web 与 server 构建
通过，包含 TypeScript 检查与 Web 包预算。新编译产物的临时 loopback 实例通过
health 200、授权 Hub 版本 1.0.0、匿名 Hub 401、HTML／资源 HEAD 200，以及
SIGTERM 后子进程真实关闭且退出码为 0；未强制清理。原生、上游、更新与安装
适配器均禁用，未变更生产实例。完整后端、原生／容器、真实上游与远端 CI 仍未验证。

通用恢复回执持久化缺口，以及模型同步写入的授权连续性（`AOD-API-COMP-005`）
仍独立未闭环。结构／生成文件覆盖与未证实的 UI 假设继续明确保留；哈希与定点
测试成功都不会将它们提升为语义审查通过。

## 强制发布门禁

`pnpm check:publication` 仍用于草稿隐私／版本检查。
`pnpm check:publication:release` 还核对首次历史／身份、干净工作树、许可证存在、
当前完整语义证据、没有未闭环问题记录，以及[发布决策](review/release-approval.json)。

决策文件刻意保持 pending。`inheritedRights`、`artifactAttribution`、`acceptance`
和 `releaseAuthorization` 各自必须具备：

- `status: "approved"`、真实 `approvedBy` 与 ISO UTC `approvedAt`；
- 非空 `evidence`，条目包含仓库相对 `path` 和精确 `sha256`；
- 根级 `sourceVersion`、`sourceSha256` 与已审查源码清单一致。

源码摘要包含可发布文件及字节，仅排除决策文件自身和自记录文件台账；台账另行
与当前全部可发布字节核对。证据不得引用决策文件自身、被忽略的私有文件、缺失
文件或符号链接。源码变更使批准失效。缺失／损坏决策封闭失败，不输出其内容。
超过长度门槛的 LICENSE 只能证明文件存在，不能证明获得了分发批准。

检查器不能认证签名者、证明法律权属或证明证据文档真实。维护者仍必须核查原始
记录和实际分发范围；禁止由测试自动填入批准。历史覆盖观察需明确对账，不能删除
或静默改标签来放行问题注册表。
源码修复使用 `fixed-targeted-verified` 与 `remediation`；已证伪问题使用
`reviewed-no-finding`，已完成的证据缺口使用 `verification-complete`，后两者
记录于 `resolution`。关闭必须有摘要、非空 `testEvidence`、边界及明确的
`liveAcceptance: false`；实机验收仍是独立门禁。

## 仍需人工决定

1. 明确继承源码／资源的权利人及 Apache-2.0 发布权限，包括其他贡献者权益与声明。
2. 明确只发源码还是同时发 Web／镜像／原生包；逐发行物审核。可选外部智能体由用户
   自行安装，不被本项目重新授权。
3. 确认公开联系邮箱可用及私有安全报告流程。
4. 提供缺失网关实现及可核验身份；其可执行探针属于受信任运维代码，不是沙箱或只读保证。
5. 用全新隔离账号安排真实浏览器／键盘／触控／无障碍及宣称平台／上游验收，
   不隐含授权业务历史重放。
6. 适用阻断关闭后，另行明确批准发布。

此流程不凭空生成最终 NOTICE、权属批准或完整验收。参阅
[许可调查](licensing-review.md)与[原生安全](native-security.zh-CN.md)。
