# English and Simplified Chinese

**English · [简体中文](i18n.zh-CN.md) · [Documentation](README.md)**

Supported locales are `en` and `zh-CN`. The main README and default documentation
are English; `README.zh-CN.md` and paired guides provide Simplified Chinese.

## Implementation

[`i18n.ts`](../apps/web/src/lib/i18n.ts) chooses an explicit stored preference
before browser language, uses independent `agentopsdeck.locale` storage,
updates the document language and loads Chinese lazily.
[`translations.ts`](../apps/web/src/lib/translations.ts) uses English source
strings as typed keys and contains the Chinese dictionary. English is also the
fallback while Chinese loads. Parameters are plain text, not HTML templates.
User messages, file names, provider diagnostics and logs must not be translated
as arbitrary catalog keys or rewritten to hide failures.

## Checks and contribution

```sh
pnpm check:i18n
node scripts/run-script-tests.mjs check-web-i18n.test.mjs check-i18n-catalog.test.mjs documentation.test.mjs
node scripts/run-source-tests.mjs web lib/i18n.test.ts
```

The JSX guard covers static text and accessible title/placeholder/alt/aria-label
attributes, including conditional fallbacks. Exact exceptions are for proper
names and literal machine commands, not user-visible untranslated prose.
The catalog guard checks duplicate/empty entries, interpolation parity and
literal `t`/`translate`/`translateMessage` calls throughout `.ts` and `.tsx`.
Existing tests cover locale fallback, English exactness and safe interpolation.
Documentation tests verify paired guides, navigation and common setup examples.

When adding UI copy, add its English key and Chinese value together, preserve
every interpolation parameter, call the existing translation hook and provide
localized accessible labels. Update both guides when behavior changes. Do not
maintain a parallel locale implementation.

## Explicit boundaries

Dynamic keys are counted but not exhaustively evaluated; TypeScript and targeted
feature tests provide additional coverage. Server/provider diagnostics and user
content are not a promise of translated output. Browser preference/storage failure,
Chinese loading failure, line wrapping and assistive-technology rendering still
require real browser testing; source checks alone do not establish visual or
keyboard/touch accessibility acceptance.
